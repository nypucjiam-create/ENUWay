# ENUWay тестілеу стратегиясы

## Мақсат және сапа қақпалары

Стратегияның мақсаты — ENUWay оқу инкрементіндегі сапар іздеу, сапар құру және орын броньдау сценарийлерін релизге дейін тексеру. Өзгеріс `main` тармағына тек линтер, автоматты тесттер, кемінде 60% қамту, контейнер құрастыру, Trivy және gitleaks тексерулері өткеннен кейін түседі.

## Деңгейлер және автоматтандыру

| Деңгей | Үлес | Нені тексереді | Құрал | Қашан іске қосылады |
|---|---:|---|---|---|
| Модульдік | 45% | іздеу сүзгісі, 1–4 орын шегі, артық және қайталанған бронь | pytest | әр commit және PR |
| Интеграциялық API | 25% | сапар құру → іздеу → броньдау ағыны, HTTP кодтары | Flask test client + pytest | әр commit және PR |
| Сквозной | 10% | браузердегі іздеу мен броньдау | Playwright, стенд дайын болғанда | PR және релиз кандидаты |
| Жүктемелік | 10% | 30 бір мезгілдегі қолданушыда іздеу p95 < 800 мс, қате < 1% | k6 | релиз кандидаты |
| Қолмен және UAT | 10% | түсініктілік, қабылдау сценарийлері, теріс жағдайлар | хаттама | әр маңызды инкремент |

Автоматтандыру мақсаты — қайталанатын функционалдық тексерулердің кемінде 80%-ын CI арқылы орындау. UX бағасы мен тапсырыс берушінің қабылдауы қолмен қалады.

## Тест деректері

- нақты студенттің аты, телефоны, ENU поштасы және нақты сапар тарихы қолданылмайды;
- атаулар `Тест қолданушы 01` тәрізді жасанды мәндермен беріледі;
- `scripts/generate_test_data.py` бірдей `seed=20261112` арқылы 20 қайталанатын жазба жасайды;
- CI әр іске қосылғанда деректерді жаңадан құрады;
- логтарда құпия токен, cookie, толық e-mail және дәл мекенжай жазылмайды;
- тест аяқталғаннан кейін уақытша деректер жойылады.
