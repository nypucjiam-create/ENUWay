# ENUWay жұмыс ағыны

Бұл бөлім ENUWay командасының тапсырманы идеядан тексерілген нәтижеге дейін қалай өткізетінін бекітеді. Процесс GitHub Projects тақтасына арналған және нақты күту кезеңін, WIP шектеулерін, өту саясаттарын, екі спринттің мақсатын және метрикаларды қамтиды.

## Тақта кезеңдері

| Кезең | Мағынасы | WIP шегі | Кіру шарты | Шығу шарты |
| --- | --- | ---: | --- | --- |
| Backlog | Басымдық берілмеген немесе кейінге жоспарланған жұмыс | шектеусіз | мәселе мен күтілетін нәтиже жазылған | басымдық қойылып, DoR орындалған |
| Ready | Орындауға дайын жұмыс | 6 | DoR толық, жауапты анық | орындаушыда бос capacity бар |
| In Progress | Нақты орындалып жатқан жұмыс | әр адамға 2, командаға 6 | карточка Ready күйінде және иесі бар | нәтиже тексеруге дайын немесе сыртқы кедергі пайда болды |
| Waiting | Сыртқы шешімді, деректі немесе қолжетімділікті күту | 2 | кедергі, оның иесі және қайта тексеру күні жазылған | кедергі жойылды немесе жұмыс қайта жоспарланды |
| Review | Қабылдау критерийлері бойынша тексеру | 3 | нәтиже сілтемесі мен тексеру дәлелі бар | DoD толық орындалды немесе түзету қажет |
| Done | Қабылданған және қайтарылмайтын нәтиже | шектеусіз | DoD толық орындалған | өзгеріс болса жаңа карточка ашылады |

## Өту саясаты

1. Backlog → Ready: пайдаланушы құндылығы, қабылдау критерийлері, бағасы, тәуелділіктері және жауаптысы көрсетіледі.
2. Ready → In Progress: орындаушы жұмысты бастайды және өз WIP шегін асырмайды.
3. In Progress → Waiting: сыртқы кедергі карточкада нақты жазылады. Кедергінің иесі мен қайта қарау күні міндетті.
4. Waiting → In Progress: қажетті шешім немесе қолжетімділік алынғаны дәлелмен белгіленеді.
5. In Progress → Review: нәтиже сілтемесі, қабылдау критерийлерінің тексеруі және орындалған тесттер тіркеледі.
6. Review → In Progress: табылған ақау немесе толық емес критерий карточкада жазылады.
7. Review → Done: DoD тексеру тізімі толық орындалады. Done карточкасы бұрынғы күйге қайтарылмайды.

Карточка нақты кезеңге өткен күні тақтада сол күні жылжытылады. Бұл саясат келесі спринттерде cycle time және time in status көрсеткіштерін GitHub Projects-тен тікелей алуға мүмкіндік береді.

## Спринт 1

**Кезеңі:** 16.09.2026–29.09.2026.

**Мақсаты:** команда ENUWay шешімінің жұмыс кеңістігін, ортақ жеткізу ережелерін және пилоттық пайдаланушы зерттеуінің бастапқы жоспарын көрсете алатын күйге жеткізеді.

**Көрсетілген нәтиже:** репозиторий құрылымы, GitHub байланыстары, пилоттық сұхбат жоспары және жеткізу моделі жөніндегі шешім.

## Спринт 2

**Кезеңі:** 30.09.2026–13.10.2026.

**Мақсаты:** тапсырыс беруші ENUWay MVP талаптарын, жеткізу жоспарын және ықтимал аяқталу болжамын бір пакетте қарап, келесі қадамды бағалай алады.

**Көрсетілген нәтиже:** ЛЗ 4 талаптар пакеті, ЛЗ 5 жеткізу жоспары және ЛЗ 6 ықтималдық болжамы.

## Метрикалар

| Метрика | Спринт 1 | Спринт 2 | Өзгеріс |
| --- | ---: | ---: | ---: |
| Throughput | 2 элемент | 3 элемент | +1 |
| Орташа cycle time | 6,99 сағ | 1,25 сағ | −5,74 сағ |
| p85 cycle time | 11,62 сағ | 2,17 сағ | −9,45 сағ |
| Throughput тәулігіне | 0,14 | 0,21 | +0,07 |
| Уақытпен өлшенген орташа WIP | 0,042 | 0,011 | −0,030 |

Little’s Law тексеруі екі спринтте де сәйкес: `WIP ≈ throughput/күн × орташа cycle time/24`. Спринт 1 үшін 0,042 ≈ 0,042, Спринт 2 үшін 0,011 ≈ 0,011.

## CFD және тар орын

CFD Спринт 2-де бір элементтің 8 қазанға дейін Backlog күйінде қалғанын көрсетеді. Сондықтан көрінетін тар орын орындау кезеңінде емес, жұмысты бастауға дейінгі күтуде болды. In Progress жолағы кеңеймеген. Бұл қорытынды спринт басталғанда барлық элемент Backlog ішінде болды деген ашық болжамға сүйенеді.

## Дерек сапасы

Ағымдағы GitHub Projects тақтасында Done карточкалары жоқ. Сондықтан бұл зертханада In Progress және Done уақыттары immutable Git commit тарихынан ретроспективті түрде қалпына келтірілді. Ready және Review уақыттары дәлелденбегендіктен, оларға мән ойдан қосылмады. Excel файлы бастапқы журналды, формулаларды, CFD-ні және шектеулерді бірге сақтайды.
