# ENUWay сервисі қолжетімсіз болғандағы runbook

## Белгі және триггер

Health-check екі рет қатарынан HTTP 200 қайтармайды, жауап 20 секундтан ұзақ немесе пайдаланушылар іздеуді аша алмайды. Оқиға P1 деп басталады; дерек жоғалуы не қауіпсіздік бұзылуы болса P0-ге көтеріледі.

## Алғашқы 10 минут

1. Инцидентті GitHub issue түрінде ашып, басталу уақытын және әсерді жазыңыз.
2. Incident commander — Нурислам. Ол рөлдерді бөледі және әр 15 минут сайын күйді жаңартады.
3. Тексеру:

```text
curl --fail --show-error --max-time 20 http://localhost:8000/health
docker ps --filter name=enuway
docker logs --tail 100 enuway
```

4. GitHub Actions ішіндегі соңғы жасыл CI run мен релиз commit SHA-ны тексеріңіз.
5. Құпия токендер мен жеке деректі журналға көшірмеңіз.

## Диагностика

- контейнер жоқ: соңғы жасыл бейнені қайта іске қосу;
- контейнер қайта-қайта тоқтайды: `docker logs` арқылы міндетті баптау қатесін тексеру;
- health жұмыс істейді, бірақ іздеу істемейді: `/api/rides` smoke-тестін орындау;
- жаңа релизден кейін басталды: кері қайтару чек-листін іске қосу;
- GitHub Actions істемейді: workflow annotation мен action tag қолжетімділігін тексеру.

## Қалпына келтіру

```text
docker stop enuway
docker rm enuway
docker run -d --name enuway -p 8000:8000 enuway:<LAST_GREEN_SHA>
curl --fail http://localhost:8000/health
```

Содан кейін іздеу, сапар құру және броньдау smoke-тесттері орындалады. 30 минут ішінде екі рет health-check сәтті өтсе, сервис қалпына келді деп есептеледі.

## Эскалация

- 15 минутта себеп табылмаса — Альфарабиге және Нурайға эскалация;
- 30 минутта қалпына келмесе — тапсырыс берушіге ықпал мен болжамды уақыт хабарланады;
- дерек жоғалуы, рұқсатсыз қолжетімділік немесе 60 минуттан ұзақ үзіліс — P0 және кері қайтару міндетті;
- 48 сағат ішінде кінәсіз postmortem жасалады.

## Тексеру хаттамасы

Runbook-ты осы компонентті жазбаған қатысушы орындайды. Тексеруші, күні, басталу және аяқталу уақыты сыртқы UAT сессиясында толтырылады; мақсат — 10 минут ішінде диагноз және 20 минут ішінде қалпына келтіру.
